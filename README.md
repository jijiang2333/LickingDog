# 心动雷达 · LickingDog

抖音 iOS 插件，版本 **1.0-1**。入口仅在 **抖音 → 设置 → 心动雷达**。

选择互关好友，或输入完整抖音号核对用户后添加。在你刷抖音时，轻量检测这些用户的可见数据，并记录喜欢列表中的新发现作品。

| 功能 | 行为 |
| --- | --- |
| 页面导航 | 全屏进入插件设置；深浅色跟随抖音 |
| 选择对象 | 从抖音本地联系人读取互关好友；真实头像、备注优先、备注/昵称/抖音号搜索、加载动画、单选/多选；点选后直接确认添加，也可继续多选；输入抖音号先匹配联系人，再调用宿主用户搜索；最多 20 人 |
| 数值变化 | 获赞、关注、粉丝、喜欢；保存变化前后数值和差值；资料返回即提醒，独立于喜欢列表请求 |
| 个人简介 | 随资料请求检测，不增加请求；记录修改前后原文与发现时间；个人页可复制简介，档案可筛选、搜索前后内容、逐项复制或复制全部；换行、空格和 emoji 保留 |
| 喜欢作品 | 保存作者、作者抖音号、文案、作品 ID、链接、发布时间、发现时间；打开作品由抖音原生页面展示 |
| 提醒 | 只在前台弹出，自适应深浅色；不自动关闭；出现后 2 秒防误触；新喜欢作品可直接打开；多项数量变化完整展示 |
| 资料展示 | 备注、昵称和抖音号分开显示；个人页展示四项数据、最近变化和检测状态；复制提示在上方显示深浅色自适应勾选胶囊 |
| 刷新间隔 | 默认 30 秒，自定义 30–300 秒；手动检查仍遵守间隔 |
| 档案清理 | 单条左滑删除、一键全部清空；保留 1 / 7 / 30 天或不按时间清理；默认 7 天、500 条，上限可选 100 / 500 / 1000 条 |
| 多账号 | 关注对象、设置、基线和记录按当前抖音 UID 分开保存 |

首次读取只建立基线，已有喜欢不会刷屏。可以暂停单个对象，或重建检测基线。清空档案不会丢失基线，不会把刚删除的记录立即重新写回。

简介首次成功读取（包括升级后第一次读取）只建立基线，之后修改、清空及从空简介恢复都会记录。缺字段、`null`、类型异常和请求失败不会当成清空，也不会覆盖上次成功内容。个人页区分本次未返回与空简介，并显示读取时间和最近变化时间；单独复制空简介会清空剪贴板，复制全部资料则用 `（空简介）` 标明。简介变化和其他档案共用删除、保留天数、数量上限及账号隔离规则；关闭弹窗仍会保存记录。

## 检测与资源使用

只在 `UIApplicationStateActive` 时启动请求。失去前台焦点即停止定时器，取消插件发起的监控请求，忽略迟到结果；不使用后台任务、定位、音频保活、推送或常驻轮询。

插件数据操作共用串行队列，相邻操作至少间隔 2 秒。联系人读取仅在打开选择页、手动刷新或查号时触发，不参与周期检测。每个对象按其自身间隔到期检测；多数情况每轮为一次资料请求、一次喜欢列表请求。喜欢首屏最多 30 项，遇到连续新增较多的情况最多补到 3 页 / 90 项。多人检测包含排队时间，因此实际周期可能长于配置值；异常重试最长退避至 300 秒。

仅持久化轻量文字和 URL；可见列表按需加载头像，最多 3 个并发，单图最多 2 MB，解码为 128 px 缩略图，内存缓存最多 4 MB / 80 张，切后台取消，不保存图片文件；不下载封面或视频。每人保留最近最多 300 个作品 ID 用于去重。未变化状态最多每 30 秒合并落盘，新增档案和用户设置尽快落盘；JSON 编码和原子写入在串行后台队列执行。自动清理只在抖音前台机会执行，回到前台时也会清理到期记录。

## 数据边界与兼容性

面向抖音 **39.9.0** 适配。其他版本请自行测试。
